## 1. The one lesson worth carrying forward

Five separate bugs shipped today past checks that were supposed to catch them. In every case the
check confirmed something adjacent to the property that mattered:

| Bug | What the check proved | What it needed to prove |
|---|---|---|
| Pages could not scroll | A 900x2400 screenshot showed the whole page | That the page **scrolls** at a phone viewport |
| John's agent mode was dead | The API returned a reply **in voice** | That the behaviour **unique to agent mode** fired |
| The stripper deleted emphasis | One short-emphasis example survived | That **long** emphasis survives too |
| Narration came back in brackets | Asterisk narration was gone | That **narrating** was gone, in ANY notation |
| The favicon was an unreadable blob | The file existed and loaded | That the mark is legible **at 16px** |

**A verification that cannot fail is not a verification.** Before claiming something works, ask what
result would look identical if it were broken. A tall screenshot cannot tell a scrolling page from a
locked one. A reply in character only proves the persona loaded.

Each now has a real check: `scrollcheck` drives Chrome at 390x844 and asserts the container moved;
agent mode is tested by the sales swerve and the by-name Rex accusation; the stripper has 22 cases
covering emphasis and every notation as well as narration; icons are rendered at their real pixel
size, from the LIVE file, before being called done.

## 2. Deploy — unchanged, but read §1 first

Push-to-deploy is live: a systemd timer (`frendz-autodeploy.timer`, ~60s) pulls, builds and restarts
`frendz-and-foes.service` **only if the build passes**. So: commit, push, wait 60-90s, then VERIFY.

**A `200` is NOT proof** — unknown paths fall back to `index.html` and also return 200. Always check
content-type and size against a negative control:

```bash
curl -s -o /dev/null -w "type=%{content_type} size=%{size_download}\n" https://playzoo.snapaweb.com/crew/rex-warning.png
# -> image/png 491712   (matches the local file)
curl -s -o /dev/null -w "%{content_type} %{size_download}\n" https://playzoo.snapaweb.com/crew/does-not-exist.png
# -> text/html 2495     <- what a MISS looks like, also 200

curl -s https://playzoo.snapaweb.com/ | grep -o 'index-[A-Za-z0-9_-]*\.js'   # must match apps/web/dist/assets/
```

## 4. Phase 1 (SQLite) — DONE and live

`backers.js` and `backerCodes.js` now run on SQLite with **byte-identical exports**, so `index.js`
needed no changes. Records keep their camelCase shape via one `rowToBacker()` mapper.

- **Migration is idempotent**: each module imports its legacy JSON only if its table is empty, inside
  a transaction. A partial import would be worse than none, because the is-it-empty guard would then
  never fire again. The JSON files are **kept as backup**, never deleted.
- `sqlite.js` is imported **dynamically**: a static import that threw would kill the server; this way
  a DB failure degrades to the existing fail-safe (codes unavailable, signup stays CLOSED).
- `redeemCode` now claims **atomically** (`UPDATE ... WHERE redeemed_by IS NULL` + `changes` check).
  The old read-then-write let two simultaneous signups take one code.
- The append-only `events` table is now being written: signup, redeem, sort, mint, password set,
  profile update, and both migrations. **That table is what the audit-log screen will read.**
- DB lives at `apps/server/data/playzoo.db`; `apps/server/data/` is gitignored.

**Phase 2 remains:** subscriptions + entitlements + Stripe wiring points; migrate chat + brands
(`db.js`, `auth.js`) onto SQLite; email hooks. Stripe and email are deferred by the owner — build the
model and hook points, not the integrations.

## 5b. Stage directions: cover the BEHAVIOUR, not one syntax

After asterisk narration was cleaned up, the model started emitting the same thing in **square
brackets** - `[Leaning back, a satisfied smirk on his face.]` - which never touched a single regex.
Fixing one notation appears to have pushed it onto another.

- **Brackets are stripped unconditionally.** Nobody speaks in square brackets, so there is no
  emphasis meaning to protect. Asterisks need the position test only because they double as emphasis.
- **Parentheses are conservative** - removed only when the span opens with an action verb, so
  `(leans back)` goes and `(and I mean it)` stays. Parentheses ARE used in real speech.
- The prompts now forbid stage directions by notation name. That is a nudge, not the defence: the
  prompt already said "no stage directions" and the model ignored it.
- **If narration reappears in a form not listed here, add it to speech.js AND speech.test.mjs.**

## 5c. Icons: different sizes want different marks

The tab icon was `/brand/icon-app.webp` - Rex's face on a dark navy tile. At the 16 CSS pixels a tab
strip gives it, that portrait collapses into an unreadable smudge, and the navy vanishes on a dark
strip. The file was never wrong; a portrait cannot survive a 32x downscale.

- Tab icon is now `/favicon.ico` (real 16/32/48 bitmaps) + `/brand/favicon.png`: the pith helmet
  alone on brand violet - ONE bold shape, legible on light AND dark strips.
- `apple-touch-icon` and the PWA manifest still use Rex's face **on purpose**: those render at 192px+
  and have the pixels for it.
- `brand/icon-app.webp`, `web/icon-app.png` and `crew/rex-keeper.png` are all the SAME art baked onto
  the navy tile, so cropping any of them drags the navy along. The transparent source is
  `crew/rex-bust.png`.
- **Always render an icon at its real size before shipping it** - and look at the large master too:
  the helmet crop sliced Rex's cheeks off in a straight line, invisible at 16px and obviously wrong
  at 48px.

## 6. Layout trap that will recur

`index.css` sets `body { overflow: hidden }` with `html/body/#root` at `height:100%`. That is
**correct** for the game screens (`/play`, `/control`, `/display`) — a party game on a phone or TV
must not scroll or rubber-band. But a **document** page laid out with `min-h-full` inside that locked
body has no scroll container, so everything below the fold is unreachable.

Every document route must carry its own `h-full overflow-y-auto`. `/ask-john`, `/club`, `/founder`
now do; `/admin` always did. **Do not "fix" this by unlocking the body globally** — that breaks the
games. Any new document-shaped route needs the same treatment, checked at a phone viewport.
